## Goal

Prepare the next independently mergeable, dormant Windows deterministic-verification foundation after TSK-0048. Add a portable, checked 64-bit Win32 `STARTUPINFOEXW` and process/thread creation-attribute ABI, plus fake-tested ownership of initialized attribute-list memory and role-specific `PROC_THREAD_ATTRIBUTE_JOB_LIST`/`PROC_THREAD_ATTRIBUTE_HANDLE_LIST` configurations. Worker W must have the ordered future Job list `[J_supervision]` and an inherited-handle list containing only its bootstrap-mapping handle. Payload must have the ordered future Job list `[J_supervision, J_command]` and an inherited-handle list containing only its designated stdin/stdout/stderr handles. The result is an opaque prepared *attribute resource*, not a process, Job-membership claim, inherited-capability proof, or verification executor.

All task-added tests must use pure Python/ctypes declarations and a fully injected fake Win32 API; they must not execute any real Windows Job, process, assignment, or process-attribute native operation. Retain TSK-0048's empty-Job ownership and one-shot preassignment release unchanged. Do not add any production import or activation. The published task metadata must remain `execution_approval: draft` for this MANUAL-only slice: changing it to `approved` on authoritative `main` would make this P0 task eligible for `AUTONOMOUS_PR NEXT` after its already-Done dependency. A temporary, uncommitted `approved` copy may be used only for parser validation; it must never be published or used as execution authorization. ## Scope

2. Define explicit portable ctypes `STARTUPINFOW` and `STARTUPINFOEXW` structures, pointers and flag/attribute constants needed by this task only. Check complete x64 size, 8-byte structure alignment, field offsets and signedness: `STARTUPINFOW == 104` bytes with fields at offsets `cb=0`, `lpReserved=8`, `lpDesktop=16`, `lpTitle=24`, `dwX=32`, `dwY=36`, `dwXSize=40`, `dwYSize=44`, `dwXCountChars=48`, `dwYCountChars=52`, `dwFillAttribute=56`, `dwFlags=60`, `wShowWindow=64`, `cbReserved2=66`, `lpReserved2=72`, `hStdInput=80`, `hStdOutput=88`, `hStdError=96`; `STARTUPINFOEXW == 112` bytes with `StartupInfo=0` and `lpAttributeList=104`; plus `BOOL`/`DWORD`/`WORD`/`WCHAR`/`HANDLE`/`SIZE_T`/`DWORD_PTR` widths. Represent Win32 `LPWSTR` fields as pointers to explicitly 16-bit `WCHAR` (or ABI-equivalent raw pointers), not host `ctypes.c_wchar_p`; include these field types in portable ABI tests. Use `PROC_THREAD_ATTRIBUTE_HANDLE_LIST == 0x00020002`, `PROC_THREAD_ATTRIBUTE_JOB_LIST == 0x0002000D`, `EXTENDED_STARTUPINFO_PRESENT == 0x00080000`, `CREATE_SUSPENDED == 0x00000004`, and `STARTF_USESTDHANDLES == 0x00000100`; no process-creation API is invoked.
3. Define checked, injectable bindings for exactly `InitializeProcThreadAttributeList`, `UpdateProcThreadAttribute`, and `DeleteProcThreadAttributeList` with their actual Win32 signatures (`BOOL`, `BOOL`, `VOID` respectively), `use_last_error=True` for real lazy DLL acquisition, and immediate numeric WinError capture on failure. The first NULL-list sizing call with attribute count exactly 2 must return zero BOOL and the expected `ERROR_INSUFFICIENT_BUFFER` (`122`) with an acceptable nonzero `SIZE_T`. Copy the native error before any other native call, without treating the expected sizing failure as successful initialization. A successful BOOL is any nonzero *signed 32-bit integer* (including `-1`); reject Python `bool`, `None`, out-of-range integer or malformed fake return, rather than relying on truthiness. All reserved flags/previous/return pointers must be zero/NULL, and any unexpected status or length must fail before an initialized resource is published.
4. Define two closed, role-specific input shapes: W receives one *borrowed* `J_supervision` handle and one borrowed designated bootstrap-mapping handle; payload receives two *borrowed* ordered Job handles and exactly three borrowed designated stdin/stdout/stderr handles. Reject NULL, invalid/pseudo/out-of-range/duplicate/overlapping numeric handles and extra/missing/unlabeled entries. The builder itself fixes the required Job-list order; it cannot detect a caller placing the wrong valid OS handle under a role-labeled field. Do not accept unrestricted caller-provided Job or handle lists. Numeric checks do **not** attest handle origin, roles, access rights, membership, actual inheritability or outer-Job compatibility, which require a future trusted H-owned ledger.
5. Allocate bounded, aligned, zero-initialized opaque attribute-list memory for exactly two attributes. Require a successful second Initialize call followed by exactly one `JOB_LIST` update and one `HANDLE_LIST` update with role-specific ordered `HANDLE` arrays and `cbSize == len(handles) * sizeof(HANDLE)`. Require at least 8-byte actual pointer alignment for the allocation; cap the required list allocation at 65,536 bytes (fail-closed resource limit, not a claim about Windows platform availability). Keep the attribute-list allocation, Job-handle value array, inherited-handle value array and `STARTUPINFOEXW` storage alive as one owner through teardown; `UpdateProcThreadAttribute` value buffers must not be temporary expressions. Build a zero-initialized `STARTUPINFOEXW` with `StartupInfo.cb == sizeof(STARTUPINFOEXW)` and its list pointer; all reserved fields remain zero/NULL; payload sets `STARTF_USESTDHANDLES` with the exact three supplied handles, W does not introduce an artificial stdin/stdout/stderr policy. After successful teardown, previously exposed Python references or ctypes pointers must not be treated as usable attributes.

It supports a one-shot, concurrency-safe retirement claim so `DeleteProcThreadAttributeList` is attempted at most once after successful Initialize; never call Delete after an unsuccessful Initialize. A completed VOID Delete call is the documented termination of the list lifetime, not a checked Win32 BOOL/quiescence result. On fake-injected wrapper failure, mark teardown uncertain, retain the original causal error and bounded secondary diagnostics, and never retry or report confirmed cleanup. There is no real process-creation borrow/use interface in this task; future launch ownership must explicitly serialize use of its native pointer against retirement.

**Native ABI.** Implement 64-bit Windows C ABI structures with fixed-width ctypes scalar types, not host-platform `ctypes.c_wchar` or unvalidated `wintypes`. Confirm every field offset and `sizeof`/alignment; reject unsupported pointer width/ABI or unavailable Win32 functions before any real native operation. The new private module must not extend the four-function `CheckedJobApi` class or break `test_native_call_surface_stays_limited_to_the_four_reviewed_functions`. A narrowly typed injectable three-operation attribute API is preferable to a general subprocess manager. Lazy real acquisition is not itself permission to invoke native tests.

**Role-specific attributes.** The builder has precisely two roles: `worker` and `payload`. W's ordered Job array contains one borrowed supervision handle; its inheritance array contains only one designated bootstrap mapping handle. Payload's ordered Job array contains two distinct borrowed handles, supervision first, command second; its inheritance array contains exactly three distinct designated stream handles. Reject invalid/duplicate/same-numeric handle references across Job and inheritance arrays and unexpected structural elements. Future ownership code must independently attest that each supplied valid handle actually has its declared role. Use exactly two attribute entries per object: `JOB_LIST` and `HANDLE_LIST`, with exact byte lengths, non-NULL pointers, zeroed reserved flags, and no unlisted privilege/parent/mitigation attributes. Populate payload standard handles and `STARTF_USESTDHANDLES` to match its supplied inheritance entries; do not synthesize W's standard streams.

**Allocation transaction and ownership.** Use `InitializeProcThreadAttributeList(NULL, 2, 0, &size)` for sizing. Require the documented first-call error `122` and a nonzero bounded size no greater than 65,536; allocate an aligned backing buffer and initialize exactly once with count 2. After that, if either attribute update or any Python-side construction fails (including `MemoryError` or `KeyboardInterrupt`), attempt `DeleteProcThreadAttributeList` exactly once, preserving the primary failure and recording secondary uncertainty. Keep attribute-list and `lpValue` buffers pinned through the native Delete call; on a wrapper exception, retain all backing objects in a private process-lifetime unresolved-resource quarantine rather than allowing garbage collection of memory that might still be referenced. Register a strong reference to the allocation/owner *before* the successful native Initialize may be exposed to further Python-side failures; release this reference only after a normally returned VOID Delete or a confirmed unsuccessful Initialize. The ledger has a narrowly scoped lock and exposes no pointer or handle values. Successful completion of the VOID call allows retirement of the list allocation but does not imply any OS process/Job quiescence. Never return an owner that is partially initialized or partially updated. After initialization success, the resource owner exclusively claims its deletion before releasing any lock, allowing concurrent contenders to fail immediately without a second native Delete. A completed retirement invalidates any previously observed list pointer; the task must not expose an independent use-after-retire path. No destructor/context-manager implicit success; no blind retry. The VOID Delete call has no native success value and may not be treated as a checked process/Job close.

**Borrowed handles and future bridge.** The builder does not own, duplicate, configure, close or query any handle supplied by a caller. It does not attest the actual `HANDLE_FLAG_INHERIT`, requested access, outer Job compatibility, or capability provenance. The next atomic-launch task must provide one H-owned nonempty-Job/session lifecycle and a trusted, checked capability ledger; it must separately verify inherited-handle flags/rights, serialize `CreateProcessW` use of prepared attributes against deletion, bind real process/thread handles and Job membership, and prohibit `PreassignmentJobs.release_preassignment()` after process creation. No bridge is created in TSK-0049 because TSK-0048 intentionally exposes no transferable owned handles. Nothing can resume or launch a process from the present task's API.

**Diagnostics.** Use `WindowsVerificationError` with existing stage/category enum values; `preflight` for ABI/sizing/update and `cleanup` or `close` for attribute teardown. Capture `ctypes.get_last_error()` immediately on a failed BOOL API result; `DeleteProcThreadAttributeList` returns `VOID` and cannot have a fabricated success/error status. An anomalous fake wrapper exception during Delete marks cleanup uncertainty and retains backing memory in the private process-lifetime quarantine. Sanitize unknown Python exceptions without including text, and keep first causal failure if teardown also fails. Pre-initialization errors with no initialized resource may confirm cleanup only if all actually acquired resources are accounted for; an in-flight concurrent Delete attempt or an abnormal wrapper return never grants premature cleanup confirmation. Never project native handle integers, pointer values, paths, environment, command arguments or output to errors; default repr of handle-bearing inputs/owners must also be redacted.
