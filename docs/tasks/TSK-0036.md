## Goal

Устранить подтверждённый diagnostic/observability gap operational `AUTONOMOUS_PR` v2: когда designated reviewer корректно и явно возвращает terminal verdict `BLOCKED`, harness должен сохранить и вывести ограниченный, machine-readable, provider-neutral rationale, достаточный для последующего разбора причины остановки, не публикуя raw reviewer output и не меняя существующие workflow semantics.

После TSK-0036 valid explicit reviewer `BLOCKED` должен иметь обязательный structured payload, объясняющий:

- какие binding requirements делают blocker material;
- какого класса отсутствующая authoritative информация не позволяет корректно продолжить current fixed task;
- в чём состоит проблема;
- где в supplied evidence находится основание для blocker без копирования самого evidence;
- какой exact gap отсутствует в fixed approved contract;
- какое внешнее resolution/refinement требуется перед новым explicit invocation.

Rationale является только diagnostic evidence. Он не является `RepairFinding`, не создаёт `RepairPacket`, не запускает repair, не влияет на adaptive compute routing, no-progress/cycle detection, publication, CI, Task Closure, Mode C или merge readiness.

Существующий verdict vocabulary остаётся ровно:

```text
APPROVED
CHANGES_REQUESTED
BLOCKED
```

и existing terminal semantics сохраняются:

```text
valid explicit BLOCKED
→ terminal RunOutcome.BLOCKED
→ никакого automatic retry/repair
→ continuation только через новый explicit user invocation
```

Malformed/missing BLOCKED rationale, malformed reviewer output, timeout, process failure и другие fail-closed reviewer-boundary errors также завершают invocation как `BLOCKED`, но не должны masquerade as a valid explicit semantic reviewer `BLOCKED`: существующий `verdict_is_explicit` boundary сохраняет это различие.

TSK-0036 не пытается задним числом восстановить semantic причину четвёртого TSK-0032 Mode C `BLOCKED`. Она делает будущий аналогичный terminal verdict детерминированно диагностируемым.

## Scope

1. Сохранить strict reviewer verdict vocabulary ровно `APPROVED` / `CHANGES_REQUESTED` / `BLOCKED`; новый verdict не добавлять.
2. Ввести provider-neutral closed enum `ReviewBlockerKind` или эквивалентный typed value ровно со значениями:
   - `missing_decision`;
   - `missing_scope`;
   - `missing_architecture_contract`;
   - `missing_dependency`;
   - `missing_information`.
3. Ввести immutable `BlockedReviewRationale` или эквивалентный typed value с обязательными полями:
   - `binding_bases`;
   - `blocker_kind`;
   - `problem`;
   - `evidence_reference`;
   - `blocking_gap`;
   - `required_resolution`.
4. `binding_bases` должен быть ordered non-empty tuple/list из 1–8 unique strings. Каждый element:
   - non-empty;
   - trimmed;
   - single-line;
   - длиной не более 512 characters;
   - проходит существующую provider-neutral `binding_basis` grammar validation.
   Trimmed является input invariant: parser валидирует исходную строку, не нормализует её; leading/trailing whitespace делает element malformed и не должен silently приниматься через `.strip()`.
5. Rationale prose fields должны быть bounded и single-line:
   - `problem`: 1–1024 characters;
   - `evidence_reference`: 1–512 characters;
   - `blocking_gap`: 1–1024 characters;
   - `required_resolution`: 1–1024 characters.
   Каждое поле non-empty, trimmed и не содержит `\r`/`\n`. Parser применяет semantics `validate, not normalize`: leading/trailing whitespace делает исходное значение malformed, и parser не должен silently `.strip()` его перед validation.
6. `evidence_reference` является concise locator/description supplied evidence, а не местом для цитирования/копирования `CURRENT_PATCH`, Task Execution Spec, verification logs, prompt или raw agent output.
7. Structured payload после explicit `BLOCKED` должен быть exactly one JSON object с exactly allowed top-level keys. Missing keys, unknown keys, duplicate JSON object keys, wrong types, empty/duplicate `binding_bases`, invalid `blocker_kind`, invalid binding basis, multiline or oversized fields являются malformed reviewer output.
8. Обновить shared operational reviewer output contract: first non-empty line остаётся exact verdict token. `CHANGES_REQUESTED` сохраняет существующий `RepairPacket` contract; valid explicit `BLOCKED` теперь обязан сопровождаться bounded `BlockedReviewRationale` JSON.
9. Сохранить `APPROVED` parsing semantics без нового payload requirement. TSK-0036 не является general tightening APPROVED output.
10. Сохранить existing `CHANGES_REQUESTED` repair-packet shape, binding-basis grammar, NonConvergenceDiagnosis semantics и adaptive repair behavior без изменений.

## Approved implementation approach

**A. Deliver MANUAL from fresh main.** Создать отдельную manual branch от fresh `origin/main`. Не запускать TSK-0036 через `AUTONOMOUS_PR`; task меняет structured reviewer protocol, который autonomous harness сам использует. Commit, push, PR и merge выполняются только после отдельных explicit user approvals. Recommended branch name: `manual/tsk-0036-blocked-rationale-observability`.

**B. Keep verdict semantics unchanged.** `ReviewVerdict` остаётся closed three-value enum. Новый enum классифицирует только rationale внутри valid `BLOCKED`; он не создаёт новый workflow outcome.

**C. Add one narrow blocker taxonomy.** В `model.py` добавить `ReviewBlockerKind` с exact values:
```text
missing_decision
missing_scope
missing_architecture_contract
missing_dependency
missing_information
```
Не вводить generic ontology, arbitrary provider tags, confidence score или severity ranking.

**D. Add a dedicated rationale type.** `BlockedReviewRationale` является отдельным immutable dataclass, не subclass/alias `RepairFinding`. Exact conceptual shape:
```python
@dataclass(frozen=True)
class BlockedReviewRationale:
    binding_bases: tuple[str, ...]
    blocker_kind: ReviewBlockerKind
    problem: str
    evidence_reference: str
    blocking_gap: str
    required_resolution: str
```

**E. Reuse binding-basis grammar without importing repair semantics.** Для каждого `binding_bases` element переиспользовать current `_validate_binding_basis(...)` semantics после blocked-rationale-specific bounded single-line validation. Validation применяется к исходной строке: leading/trailing whitespace отклоняется, а не silently исправляется через `.strip()`. Rationale может указывать несколько bases, потому что real missing-decision/contract blocker может возникать из conflict между несколькими authoritative requirements. Ordered input сохраняется; duplicates запрещены.

**F. Parse BLOCKED with an exact bounded schema.** В `agents.py` добавить narrow parser/helper для blocked rationale. Top-level JSON object имеет exact key set; unknown/missing/duplicate keys fail closed. `binding_bases` — list 1..8 unique strings. Prose fields non-empty/trimmed/single-line and bounded exact limits from Scope. Для `binding_bases` и всех prose fields действует `validate, not normalize`: untrimmed input отклоняется без `.strip()` normalization. Duplicate JSON keys должны быть detectable/rejected для нового BLOCKED payload, не silently last-value-wins.

**G. Do not broaden CHANGES_REQUESTED parsing.** Existing repair-packet parser, finding fields, optional extra provider-neutral finding metadata behavior, NonConvergenceDiagnosis and existing tests остаются semantic source of truth для repairable defects. TSK-0036 не использует opportunity to refactor or tighten unrelated repair JSON.

**H. Preserve APPROVED compatibility.** `APPROVED` остаётся existing valid explicit verdict without required rationale payload. General trailing-output tightening для APPROVED находится вне scope.

**I. Maintain explicit-vs-synthetic distinction.** Existing `_blocked_structured_review(...)` или equivalent remains the representation for malformed/process fail-closed cases and leaves `verdict_is_explicit=False`, `blocked_rationale=None`. Only successful parse of first-line `BLOCKED` plus complete valid rationale produces `verdict_is_explicit=True`.

## Known constraints / edge cases

- Fourth-pilot explicit Mode C `BLOCKED` semantic reason is irrecoverable from current harness evidence. TSK-0036 must not encode a guessed cause, a special case for TSK-0032, candidate SHA, PR #117 or saved patch.
- Diagnostic branch and saved patch remain forensic artifacts only. They must not become correctness inputs, fixtures tied to production SHA, resumable state or special replay source.
- `BlockedReviewRationale` is model-authored diagnostic data. Python can validate shape, bounds, allowed binding-basis grammar and blocker taxonomy, but cannot prove semantic truth of reviewer prose. Correctness authority remains the designated reviewer verdict plus existing deterministic boundaries; rationale helps diagnosis, not automatic policy.
- Bounded allowlisted fields reduce accidental transcript leakage but do not constitute a general secret-detection system. `evidence_reference` is deliberately a concise locator rather than arbitrary evidence body.
- Multi-basis blockers are valid. A missing human decision may arise only after comparing two otherwise authoritative requirements; forcing exactly one `binding_basis` would lose material context. The bounded 1..8 ordered unique list handles this without introducing a requirement graph.
- Existing `repo:*` binding basis receives syntactic validation only. TSK-0036 does not add a repository-anchor registry or prove that arbitrary repo references exist.
- Bare `BLOCKED` changes meaning under the operational structured parser: it is now malformed because semantic rationale is mandatory. Existing tests/fixtures that used bare BLOCKED merely as a convenient valid terminal verdict must be migrated intentionally; negative parser tests should keep bare BLOCKED.
- Legacy `parse_reviewer_verdict(...)`, if retained, is a token utility and not the operational v2 structured contract. Its ability to identify a `BLOCKED` token must not allow operational callers to bypass rationale validation.
- `raw_output` remains useful internally during the immediate parser boundary and may remain in `StructuredReviewResult`; TSK-0036 only forbids propagating it into durable/in-memory audit projections exposed through `RunResult`/CLI.
- An explicit valid `BLOCKED` is recorded in GateHistory but is not a rejected candidate. The run terminates; there is no repair candidate against which no-progress/cycle logic should operate.
- Malformed BLOCKED rationale is a fail-closed protocol error, not a semantic explicit reviewer decision. Therefore it intentionally creates no explicit reviewer attempt/metric entry under current `verdict_is_explicit=False` semantics, while `blocked_reason` still explains the parser failure.
- A reviewer process can emit a valid-looking `BLOCKED` payload and then exit non-zero. Existing process-status precedence remains authoritative: non-zero process exit is process failure, not accepted semantic rationale.
- A reviewer timeout may have produced partial stdout containing a BLOCKED JSON fragment. Existing timeout handling remains fail closed and does not accept partial rationale.
- Additional unknown BLOCKED payload fields are rejected rather than ignored. This is intentionally stricter than some existing RepairFinding forward-compatible metadata behavior because this new object is a bounded terminal observability surface with no legacy compatibility requirement.
- The rationale field limits are diagnostic-surface limits, not model token budgets and not repair iteration budgets.
- `ReviewGateMetrics` intentionally excludes blocked rationale bases. This prevents diagnostic rationale from altering convergence metrics or later routing behavior and preserves TSK-0030/TSK-0031 semantics.
- `RunResult.blocked_reviews` is a tuple even though current valid workflow normally yields at most one explicit BLOCKED, because diagnostics should preserve recorded facts rather than silently drop unexpected future/internal entries.
- A deterministic orchestrator blocker such as repeated candidate, stale evidence, moved PR head or required-CI failure is not a reviewer semantic BLOCKED and must not fabricate `BlockedReviewRationale`.
- TSK-0035 required-CI logic may still be unvalidated by a complete real production run if a reviewer blocks earlier. TSK-0036 does not change that logic; the next fresh TSK-0032 pilot remains the empirical continuation.
- If the fifth production TSK-0032 pilot returns Mode C `APPROVED`, it can proceed to production validation of TSK-0035 required-CI stabilization. If it returns valid explicit `BLOCKED`, `review_blocked_json` should provide the first preserved grounded rationale for deciding whether a real missing contract, evidence gap, or reviewer-classification issue exists.
- If future evidence shows that `BLOCKED` rationale itself needs a richer machine-readable taxonomy, that should be a separate reviewed task. TSK-0036 deliberately introduces only the smallest taxonomy already implied by current canonical BLOCKED semantics.
