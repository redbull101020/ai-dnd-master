Preserve all existing Command/Result/Event contracts and out-of-Combat Attack behavior. The broad Phase 3 Targeting/Monster actions/Movement capabilities remain open.

This execution-ready specification is approved for implementation **only after** Architecture §3.40, DEC-0057 and this task are published to authoritative `main` and TSK-0051 has authoritative terminal `Done` status. The architecture decision was accepted on 2026-11-01, but the reach gate is not yet implemented. Approval and publication do not activate `AUTONOMOUS_PR`; a separate explicit invocation on a fresh baseline is required.

3. Enforce in this **exact** order and shape for the qualifying in-Combat Goblin attack: missing `combat.positions` for `actor_id` → `ACTION_NOT_AVAILABLE`, actor id, field `"position"`; target absent from `combat.order` → `INVALID_TARGET`, target id, field `"target_id"`; target CombatPosition absent → `INVALID_TARGET`, target id, field `"position"`; squared Euclidean distance `dx*dx+dy*dy > 25` → `OUT_OF_RANGE`, target id, field None. 5. Every accepted Command must be independently observable through a **fresh** `FilesystemStateStore.load` using production V11; use a uniqueness-preserving EventMetadataProvider with canonical Event IDs. No in-encounter direct State mutation, initiative override, synthetic winning/death policy, alternate RNG, or gameplay dispatcher is allowed.
6. Verify the fixed scenario in approach item 5, including pre-roll out-of-reach rejection with **unchanged seeded RNG state (`random.Random.getstate()`), unchanged EventMetadataProvider call count and exact persisted `state.json` bytes**, then a legal Monster Move into reach and a successful Attack.
