## Goal

Выполнить первый production `AUTONOMOUS_PR` pilot на намеренно узком и полностью определённом repository-hygiene изменении:



Задача является первым реальным `AUTONOMOUS_PR` trial после завершения operational v2 и deterministic adaptive compute routing.

Она не вводит нового gameplay, architecture, task-governance или autonomous-harness контракта и не меняет существующее поведение tooling.

## Approved implementation approach

### A. Treat terminal registry as the permanent source of terminal facts

Удаляемые task specs больше не являются authoritative источником lifecycle/status.

После terminal `Done` authoritative facts живут в:

```text
docs/TASK.md
```

Именно поэтому удаление spec-файлов допустимо.

Не копировать body старого spec в `TASK.md`: terminal registry хранит только предусмотренные permanent terminal facts, а не полный execution contract завершённой задачи.

### B. Delete files; do not rewrite them

Implementation delta до prospective Task Closure должен представлять собой ровно tracked deletion:

```text
D docs/tasks/TSK-0029.md
D docs/tasks/TSK-0030.md
D docs/tasks/TSK-0031.md
```

Не заменять их tombstone-файлами, redirect-файлами, краткими history stubs или symlinks.

### C. Preserve the dependency proof created by this exact task

TSK-0032 зависит от:

```text
TSK-0031
```

Удаление `docs/tasks/TSK-0031.md` не отменяет эту dependency, потому что она уже удовлетворена authoritative terminal `Done`.

Это intentional real-repository proof already-approved semantics, а не новый contract.

Не удалять dependency из metadata TSK-0032 и не изменять selected spec во время invocation.

### D. Do not mechanically rewrite synthetic test paths

Tooling tests используют filenames вроде:

```text
docs/tasks/TSK-0030.md
docs/tasks/TSK-0031.md
```

как synthetic fixture values для тестирования parser/repository behavior.

Эти literals не являются ссылками на retained production task files.

TSK-0032 не меняет их.

### E. No compensating documentation edits

На reviewed preparation base surviving normative docs не требуют retained bodies TSK-0029..0031.

Поэтому ordinary implementation checkpoint не должен:

- редактировать `README.md`;
- редактировать `CLAUDE.md`;
- редактировать `AGENTS.md`;
- редактировать `docs/AUTONOMOUS_PR_HARNESS.md`;
- редактировать `docs/TASK.md`;
- редактировать `docs/ROADMAP.md`;
- редактировать `docs/DEFERRED.md`;
- редактировать `docs/ARCHITECTURE.md`;
- редактировать `docs/DECISIONS.md`;
- добавлять cleanup/history document.

Если fresh `origin/main` перед execution создаст новую material surviving reference, которую удаление сделает некорректной, не расширять scope автоматически: следовать normal revalidation/fail-closed behavior.

### F. Keep implementation and closure boundaries separate

Ordinary checkpoint implementation:

```text
только 3 deletions
```

Prospective Task Closure позже добавляет normal:

```text
docs/TASK.md
docs/DEVELOPMENT_LOG.md
```

changes согласно существующему operational flow.

Implementer не должен заранее включать closure edits в ordinary implementation checkpoint.

### G. No architecture or code repair fallback

Если удаление трёх terminal specs выявляет, что existing catalog/dependency implementation фактически требует retained terminal file, это не повод менять `tools/autonomous_pr/**` внутри TSK-0032.

Такой результат означает discrepancy с already-approved TSK-0029 contract и требует отдельной задачи.

TSK-0032 должен закончиться fail-closed/BLOCKED в соответствии с operational rules, а не скрыто расшириться.

## Known constraints / edge cases

- Главный intentional edge case этой задачи: `TSK-0032.depends_on == ["TSK-0031"]`, одновременно implementation удаляет `docs/tasks/TSK-0031.md`. Это допустимо только потому, что TSK-0031 уже authoritative `Done` в permanent terminal registry; dependency satisfaction не должна зависеть от retained file.
- `TSK-0029`, `TSK-0030` и `TSK-0031` остаются навсегда allocated IDs после удаления файлов.
- Старые task bodies перестанут находиться в active tree после merge, но Git history продолжает хранить их историческое содержимое; создавать отдельный archive не требуется и не разрешено этой задачей.
- Synthetic filenames внутри tests являются fixture data. Их наличие после удаления реальных files корректно.
- Task Closure TSK-0032 должна сохранить все существующие terminal rows; удаление task specs не разрешает переписывать terminal registry.
- Сам `TSK-0032.md` после `Done` останется tracked. Его возможное последующее удаление требует отдельного reviewed change и не является cleanup continuation этого invocation.
- `TSK-0023` остаётся единственным старым nonterminal gameplay draft и не должен автоматически стать selected/approved/refined после `STOP`.
- `AUTONOMOUS_PR NEXT` до публикации TSK-0032 не имеет eligible approved task; после публикации этого approved spec TSK-0032 должен стать eligible при отсутствии более приоритетного eligible task. Для первого production pilot предпочтителен explicit selector `TSK-0032`, чтобы selection itself не добавлял лишнюю переменную в operational validation.
- Relevant движение `origin/main` до или во время invocation обрабатывается существующими exact-base/revalidation rules. TSK-0032 не добавляет materiality exception.
- Любая необходимость менять autonomous code, tests, task governance или canonical gameplay docs означает выход за scope и должна приводить к fail-closed outcome, а не к repair внутри этого task.
